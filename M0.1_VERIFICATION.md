# BranchBack M0.1 — Verification Evidence

**Date:** 2026-08-08  
**Claim under test:** What BranchBack says the user believed then cannot be silently rewritten by a later ordinary application write.

## Architecture closure

| Boundary | Enforcement |
|----------|-------------|
| Domain mutations | `finalize()` → `assertInvariants()` on every public op |
| Persistence | `DecisionRepository.save` compares existing vs incoming snapshot via canonical JSON; rejects `SNAPSHOT_TAMPER` / `SNAPSHOT_CLEARED` |
| Import merge / replace | Same integrity gate before write |
| Review | Re-record moves prior review into `priorReviews`; dropping/altering prior review history is rejected |
| UI-only disables | Not relied upon for the invariant |

## Persistence tests covered

1. Commit snapshot created correctly  
2. Save + reload preserves exact historical contents  
3. Post-commit revisions cannot rewrite it  
4. Tampered snapshot write rejected at `repository.save`  
5. Import cannot silently replace existing historical snapshot (merge + replace)  
6. Invalid domain state rejected before persistence  
7. Export/import round-trip preserves historical identity  
8. Revisions remain distinguishable from original snapshot  
9. Review history cannot be silently dropped
